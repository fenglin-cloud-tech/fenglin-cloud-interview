## 二、分镜详表

### 镜 01 · 0:00–0:18（18s）｜开场：成长曲线与今日计划

- **画面与操作**：打开首页 `/`，先给「能力成长」卡（3 个点 58 / 71 / 82，雷达结构 75、内容 79、表达 77），再向下滚到「今日计划」卡：`今天 0/1 已完成 · 本周共 7 条`，任务「完善一份简历并保存」，右侧「查看 7 天计划 →」。鼠标不点击。
- **字幕**：「三场真实评分：58 → 71 → 82」→「今天只做一件事」
- **旁白**：「先看结果。同一个岗位三场面试，58、71、82。新版训练台会把最近一份报告的薄弱项拆成 7 天计划，今天只留一件最该做的事，不用自己排。」
- **录屏注意**：录前载入示例档案并刷新一次，预热成长缓存。示例档案已自动生成 7 天计划；若显示「今天没有安排任务」，先完成一场面试报告再录。

### 镜 02 · 0:18–0:32（14s）｜7 天计划：把复盘拆成每天一条

- **画面与操作**：进入「7 天计划」`/plan`：页头「训练计划 · 7 天 / 把复盘结论，拆成今天就能做的三件事」，统计「本周任务 7 / 已完成 0 / 今日进度 0/1」，下面 7 天各一条任务（完善简历 → 新建岗位做匹配 → 跑一场模拟面试 → 把答不好的题加入题库 → 写一条复盘 → 记一次真实投递 → 看成长曲线挑薄弱项）。点今天任务的圆圈，勾选完成；统计变为「已完成 1」「今日进度 1/1」。
- **字幕**：「报告里的薄弱项，拆成 7 天」→「勾掉今天这条」
- **旁白**：「计划不是让你再填一遍表：它从最近一份报告的薄弱项、到期复习和投递跟进里自动排，每天最多三条；做完打勾，首页的今日进度同步更新。」
- **录屏注意**：勾选是真实写操作，会累计到备份提醒的修改次数；本镜只勾一条，后面镜 14 的提醒自然会出现。重拍前再点一次取消即可还原。

### 镜 03 · 0:32–0:52（20s）｜模板库：起草新简历

- **画面与操作**：「模板库」→ 四张卡（技术研发 / 产品经理 / 运营·内容 / 数据分析）→「技术研发」的「按引导填写」→ 切到「项目经历」，展示问题提示、输入框、「✓ 建议这样写 / ✕ 别这么写」→ 粘贴一段项目描述，右侧实时预览 →「AI 润色初稿」（4×）→「生成初版简历」→ 自动进入 `/optimize`。
- **字幕**：「每栏都有正反例」→「生成初版，直接进优化」
- **旁白**：「没有简历也能开始。模板告诉你这一栏先写什么、长什么样，写不下去先用 AI 润色；生成后直接带着这份简历进优化。」
- **录屏注意**：首次 AI 前必须先点顶部「同意并继续」，否则润色会失败。技术研发是 6 栏，别口播成「每套六栏」。

### 镜 04 · 0:52–1:06（14s）｜简历优化：逐条应用到草稿

- **画面与操作**：`/optimize` → 03 建议栏「生成修改建议」（通常 20–60 秒，4×）→ 展开「项目经历」一条，展示「量化 / 措辞 / 结构 / 冗余」标签、「为什么改」「复制改法」「应用到草稿」→ 点「应用到草稿」→ toast「已应用到当前草稿，可随时撤销」，自动切到「对话迭代」；鼠标停在「撤销应用（1）」上，不点。
- **字幕**：「每条建议都说清为什么改」→「应用到草稿，也能撤销」
- **旁白**：「它不是泛泛夸你写得好，而是按板块指出问题，只改写法、不替你编数据。看中的一条直接应用到草稿，改错了还能撤销。」
- **录屏注意**：线上一次约生成 7 条；连续生成会触发 429，一条镜头只生成一次。应用只改本地草稿，不写回原简历。

### 镜 05 · 1:06–1:16（10s）｜目标岗位：抓取 JD

- **画面与操作**：「目标岗位」→「新建岗位」→ 岗位名称「Java 后端实习」→「从招聘页面抓取」粘贴公开招聘页链接 →「解析链接」→「已抓取《…》 N 字……未写入数据库」→「保存」→「设为当前」→「做匹配分析」。
- **字幕**：「贴链接，抓 JD」
- **旁白**：「JD 不用手抄。贴一个公开招聘页链接，服务端代抓正文，先告诉你抓了多少字，确认后才保存；抓不到会说明原因，原 JD 不会被清掉。」
- **录屏注意**：这是唯一入口，不在 `/optimize`。准备可公开访问的招聘页；抓取有 10 秒超时，别连点。

### 镜 06 · 1:16–1:28（12s）｜JD 匹配：缺什么、补什么

- **画面与操作**：「JD 匹配」→「开始匹配分析」（10–30 秒，4×）→ 匹配度圆环 →「缺 xxx」关键词 → 覆盖对照表（已覆盖 / 部分覆盖 / 缺失）→「补齐动作」。鼠标逐行下滑。
- **字幕**：「匹配分 + 缺失关键词 + 覆盖表」
- **旁白**：「匹配不是给个分就完：每条要求都对着简历找证据，标成已覆盖、部分覆盖或缺失，缺的关键词单独列出来，再给补齐动作。」
- **录屏注意**：与镜 04 的 AI 调用留出间隔，避免 429；历史诊断累积后只停 1 秒，不展开。

### 镜 07 · 1:28–1:44（16s）｜新建面试：英文与四种预设

- **画面与操作**：`/interviews` → 顶部语言「中文面试 / English」，点 English，出现说明「英文面试按简历出题，题目、逐题反馈与报告均使用英文；朗读与语音识别切换为英文」，其余三种出题方式置灰 → 点回中文。依次点预设「标准面 / HR 面 / 压力面 / 行为面」，每个停 1 秒，下方描述依次为「四轮完整流程，最接近常规校招」「重点看动机、稳定性、沟通与团队协作」「高压追问，几乎每个回答都会被继续深挖」「全行为题，重点看 STAR 与复盘深度」。最后选「标准面」+「简历 + 常见题」。
- **字幕**：「四种面试预设」→「英文场只按简历出题」
- **旁白**：「面试类型可以选标准、HR、压力或行为面，节奏和追问强度不一样；英文场会把题目、反馈和报告都切成英文，目前只支持按简历出题。」
- **录屏注意**：英文只展示选择，不真的跑一场，避免把 4 分钟耗在英文作答上。英文模式下「简历 + 常见题 / 只用常见题 / 从题库再练」是置灰的，别口播成「都支持」。

### 镜 08 · 1:44–2:16（32s）｜考场：朗读、限时、异步反馈、追问、反问口径

- **画面与操作**：
  1. 进入会话：轮次轨道（自我介绍 / 专业能力 / 行为面试 / 反问环节），右侧「第 壹 轮 · 自我介绍 · 1/1」。
  2. 点「▶ 朗读题目」→「■ 停止朗读」，旁有「语速 1.0×」；切一次语速后停止。
  3. 右上「本题限时 01:00」，等到 00:29 计时变色；下方提示「最后 30 秒计时变色；时间到会自动提交已写内容，未作答不会提交空答案」。
  4. 输入两三句 →「提交并看反馈」→ 出现「正在生成单题反馈」（10–30 秒），字幕点出「后台任务 + 轮询」。
  5. 反馈卡：结构 / 内容 / 表达三个分数、做得好的、必须改、改写示范，标「AI 生成」。
  6. 若出现「追问 1/2」「下一题是追问（…）」，停在追问标签；右侧「本场信息」显示「追问 最多 2 层，方向限于项目细节 / 数据来源 / 个人贡献」。
  7. **插入 4 秒**：切到预置的反问轮反馈卡，三维标签显示「问题相关性 / 信息获取价值 / 岗位理解」，字幕点出「反问轮单独口径」。
- **字幕**：「最后 30 秒，计时变色」→「提交后后台生成，切走不阻塞」→「追问最多两层」→「反问轮看问题质量，不看答题结构」
- **旁白**：「题目能朗读，每题按轮次限时，最后 30 秒变色，到点只提交已经写下的内容。提交后是后台任务，页面只轮询状态，切走不会丢。分数不够会追一问，最多两层；到了反问环节，评分口径换成问题相关性、信息获取价值和岗位理解。」
- **录屏注意**：
  - 先同意 AI 数据外发，否则反馈会失败。
  - 追问不是每题都有；用「压力面」或故意答得笼统一些，拍到一层追问再停。
  - 反问轮口径可在完整答完 C 后，打开报告「逐题记录」展开反问轮，拍它的三维标签；不需要在现场答满 7 题。
  - 轮次限时：自我介绍 60 秒、专业能力 150 秒、行为面试 120 秒、反问 90 秒。

### 镜 09 · 2:16–2:32（16s）｜面试报告：把追问一起沉淀成复盘

- **画面与操作**：打开 `/interviews/:id/report`：总分圆环、各轮得分、薄弱环节、建议复习点、逐题记录（带追问的题标「追问 1」）。先给顶部按钮组「复制报告 / 下载 .md / 下载 Word / 导出分享快照 / 打印 / 存为 PDF」（只展示，不点），再滚到「下一步」卡，点「含追问一起生成」→ toast「已生成 N 条复盘草稿（含追问），去补改进点」。
- **字幕**：「追问也是失分点，一起沉淀」→「报告可下载 Word / 离线快照」
- **旁白**：「报告把追问单独标出来，生成复盘时可以把追问一起沉淀，不用回考场翻记录。报告本身也能下载 Word，或导出成离线快照发给别人。」
- **录屏注意**：点「含追问一起生成」会真实新增 N 条复盘；重拍前先「重新载入示例」。本镜不点分享快照，留到镜 15 拍完整的离线 HTML，避免浏览器确认框打断节奏。

### 镜 10 · 2:32–2:42（10s）｜复盘：追问单独成条

- **画面与操作**：进入 `/reviews`，画面停在带「模拟面试·追问」标签的复盘卡：题目是追问原题、我的回答 / 实际表现 / 改进点三段；再掠过顶部筛选（搜索、「全部岗位」「全部评分」「标签」「起止日期」）。
- **字幕**：「追问单独成条，不混在主问题里」
- **旁白**：「追问会单独成一条复盘，标签直接写清来源；补改进点时，你能看到自己是在哪个细节上被问住的。」
- **录屏注意**：示例数据默认没有追问；本镜的追问复盘来自镜 09 的「含追问一起生成」。没有就只拍标签筛选，不要口播「这条就是追问」。

### 镜 11 · 2:42–2:56（14s）｜求职周报：用一周数据决定下周练什么

- **画面与操作**：进入 `/weekly`：页头「数据回顾 · 周报 / 用一周的数据，决定下一周练什么」，统计条依次为「完成面试 / 平均分 / 新增投递 · 阶段推进 / 复盘·题库 / 7 天计划」；下方「本周面试」列表、「投递阶段变化」（有则列出）、「周报正文」含一句话总结、本周薄弱项 TOP、下周建议；右上「打印 / 存为 PDF」「复制 Markdown」「生成周报」。具体数字按当周实际，不写死。
- **字幕**：「一周数据，自动成稿」→「薄弱项 TOP 直接给下周建议」
- **旁白**：「周报把这一周的面试、分数变化、投递推进、复盘和题库沉淀聚在一页，自动写出薄弱项 TOP 和下周建议；可以复制 Markdown，也可以打印成 A4。」
- **录屏注意**：正文在页面加载后就有，不用点「生成周报」等模型；「生成周报」是重新生成，别在现场点。周报的「7 天计划」按本周一至今天统计，镜 02 勾过今天这条后应显示 1/1；完成面试数会因新增场次变化，字幕不要写死。

### 镜 12 · 2:56–3:12（16s）｜题库复习：先作答，再对照上次得分

- **画面与操作**：`/bank` 顶部「记忆曲线 · 今日待复习」（N 道到期 / M 道已逾期）→「开始复习」→ 弹窗「今日复习 · 第 1 / N 题」：复盘自评、逾期天数、上次的回答、改进点 → 在「先写下你的回答（可选）」输入一两句 → 选「有点模糊」→ 结果「下次复习：某日期（N 天后 · 第 X 档）」，若该题有历史得分，同时显示「上次得分 N；本次自评『有点模糊』」。
- **字幕**：「先自己答一遍，再自评」→「和上次得分放一起看」
- **旁白**：「复习不是看一眼答案就点记住了。先写下自己的回答，再自评；系统会把这次掌握程度和上次得分放在一起，告诉你是不是真的进步了。」
- **录屏注意**：第一题通常是复盘类任务，没有上次得分；要拍得分对比，提前把 3 道复盘类到期题做完，让队列进入带「上次 xx 分」的题库题（录完「重新载入示例」还原）。点「有点模糊」会改排期，重拍需重载示例。

### 镜 13 · 3:12–3:38（26s）｜投递追踪：列表 / 看板 / 日历三视图

- **画面与操作**：`/applications` → 统计条「投递总数 3 / 进入面试 1（按历史阶段）/ 已发 offer 0 / 进行中 2 · 已结束 1 / 转化 面试 33%」→ 点「看板」：8 个阶段列，卡片落在对应列，显示投递日期、跟进日期、关联面试/复盘数 → 点「日历」：月视图，「投递 · ×××」「跟进 · ×××」事件落在日期上，可切上月/本月/下月 → 点回「列表」，打开一条带跟进日期的记录详情：下次跟进、跟进事项、阶段历史 2 条（创建投递、已投递 → 一面）。
- **字幕**：「同一批投递，三种看法」→「阶段变更自动留历史」
- **旁白**：「投递不是记流水：列表看单条进展，看板看整体卡在哪个阶段，日历看这周哪天要跟进、哪天有截止。每次改阶段都会留一条历史，漏斗按历史算，不按当前阶段。」

### 镜 14 · 3:38–3:48（10s）｜训练台收口：跟进、今日进度、备份提醒

- **画面与操作**：回首页，依次停三张卡：「今日需跟进」（云岚科技 · Java 后端实习 · 询问内推进度 · 当天日期 +「去投递追踪 →」）、「今日计划」（今天 1/1 已完成）、「备份提醒」（`你已经做了一些修改（N 次），但还没有导出过备份` +「去备份 / 稍后提醒」）。
- **字幕**：「跟进、计划、备份，首屏收口」
- **旁白**：「三条线最后都回到训练台：今天要跟进哪条投递、今天的计划做完没有、以及该不该备份。提醒不是摆设，修改攒到一定次数就会出来。」
